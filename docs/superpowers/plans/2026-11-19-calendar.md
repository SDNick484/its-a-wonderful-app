# Calendar Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is also filed as one "Prompt:" GitHub issue and run from the issue queue.

**Goal:** A Calendar tab that shows one month as a grid, with the poster of each movie the family watched on the nights they watched it.

**Architecture:** A new route-free module `watched_days.py` turns `viewings` and `sessions` into per-day entries, and one read-only route `GET /api/calendar?month=YYYY-MM` in `app.py` serves it. The tab is one new ES module, `static/js/calendar.js`, reached from a header button at `#/calendar/YYYY-MM`, in the same shape as Worth a Month?. No schema change.

**Tech Stack:** Python 3.10 to 3.13, Flask, SQLite, vanilla ES modules, pytest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-calendar-design.md` (read it with this plan; § numbers below refer to it).

## Global Constraints

- No new runtime dependency, no frontend framework or build step. ES modules: `import { x } from "./x.js";`, one `export { … };` at the end. A new JS module goes in `JS_MODULES` in `tests/conftest.py`.
- A new Python module goes in `_SPLIT_MODULES` in `app.py` and in `installer/build.sh`'s `cp` line. It never imports `app`; the route stays in `app.py`.
- The new route has `@editor_required`; `tests/test_auth.py` walks `app.url_map`.
- No schema change, no new setting, nothing new in `$DATA_DIR`.
- Dates are the host's local date (`common.today()`, `TZ`), never UTC.
- Phone-first: no horizontal scroll at 412 px and 360 px, tap targets at least 44 px, text contrast at least 4.5:1. A new text colour would go in `TOKENS` in `tests/test_theme_ui.py`; this plan adds none.
- Public repo: no family names, personal hostnames or LAN addresses in code, tests or README (`tests/test_hygiene.py`). Tests use movie titles only.
- No live network in tests. `README.md` is updated in the PR that makes the feature visible (Task 2).
- Conventional Commits, author `SDNick484 <SDNick484@users.noreply.github.com>`, one logical change per commit, one PR per task. OpenRC (`rc-service wonderful restart`), `vim`.
- Task 2 is tagged **(M)**: its PR description ends with a "Try it" note.

## Review Focus

1. **Day boundaries.** A session at 11:30 pm Los Angeles counts that evening; 1:00 am and 3:59 am count the evening before; 4:00 am counts that day; a session at 11:59 pm on Nov 30 is not in December. Tests in Task 1.
2. **Nights that did not happen.** A picked-but-never-watched `tonight` viewing and an `abandoned` one never appear. Tests in Task 1.
3. **Bad or missing `month`.** `2026-13`, `Dec`, empty, `2026-1`, `0000-12` and `2026-12-01` are 400 with the spec's message; an absent month means the current one; an empty month is `days: {}`. Tests in Task 1.
4. **No poster, or a poster that will not load.** The cell and the sheet row show the titled placeholder and the cell does not overflow. Test in Task 2.
5. **Small screens and long months.** At 360 px each of the seven columns is at least 44 px wide, the header with the new button still fits on one row, and a six-week month (Aug 2026) draws all 31 days. Tests in Task 2.

**Interfaces:**
- Consumes: `viewings._stamp(value) -> aware datetime | None`, `viewings._local(when) -> aware datetime` (host `TZ`), `viewings.NIGHT_ENDS` (4), `images.image_url(name) -> str | None`, `common.today() -> date`, `common.make_err(status, msg)`.
- Produces:
  - `watched_days.parse_month(raw: str | None) -> tuple[int, int]`: `None` is the current month from `today()`; otherwise `YYYY-MM` with month 01 to 12 and year 0001 or later, else `abort(make_err(400, "month must look like 2026-12"))`.
  - `watched_days.night_of(started_at: str) -> datetime.date | None`: the local evening a session belongs to; a start before `NIGHT_ENDS`:00 local belongs to the day before; `None` when the stamp cannot be read.
  - `watched_days.month_view(con, raw: str | None) -> dict`: exactly the §5 response, `{"month", "today", "days": {"YYYY-MM-DD": [{"movie_id", "viewing_id", "title", "year", "poster_url", "finished"}]}}`.
  - `GET /api/calendar?month=YYYY-MM`, `@editor_required`.
