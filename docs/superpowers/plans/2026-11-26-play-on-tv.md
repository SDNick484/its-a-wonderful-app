# Play on the Family Room TV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is also filed as one "Prompt:" GitHub issue and run from the issue queue.

**Goal:** Buttons on a movie's page and on the main page that get the Family Room TV ready for the movie (the streaming app open, or the disc activity started with the shelf shown) and put the movie on for tonight.

**Architecture:** A new route-free module `play.py` works out what can play a movie from the caches and starts it: it marks the viewing for tonight, posts one JSON body to a Home Assistant webhook (`HA_PLAY_WEBHOOK_URL`) and waits for the answer. `/hooks/tv` now remembers the TV's last state so `GET /api/tv` can confirm the TV got there. A new ES module `static/js/play.js` owns the tap, the polling and the messages for both screens. Home Assistant gets one script and one webhook automation, written up in `docs/home-assistant.md`.

**Tech Stack:** Python 3.10 to 3.13, Flask, SQLite, vanilla ES modules, pytest, Playwright, Home Assistant YAML.

**Spec:** `docs/superpowers/specs/2026-11-26-play-on-tv-design.md` (read it with this plan; § numbers and "decision N" below refer to it).

## Global Constraints

- No new runtime dependency, no frontend framework or build step. ES modules: `import { x } from "./x.js";`, one `export { … };` at the end, `core.js` imports nothing. A new JS module goes in `JS_MODULES` in `tests/conftest.py`.
- A new Python module goes in `_SPLIT_MODULES` in `app.py` and in `installer/build.sh`'s `cp` line. It never imports `app`; routes stay in `app.py`; tests patch `app.X`.
- New routes have `@editor_required`; `tests/test_auth.py` walks `app.url_map`. No new public route.
- Schema changes go through `db.migrate()`, which must work from a v1 database and be idempotent; `SCHEMA_VERSION` becomes `"2"`.
- The one new setting, `HA_PLAY_WEBHOOK_URL`, goes in `.env.example` (comment line above it), `settings.py`, the installer's `add_setting` list and the init script's `export` line, and in `SPEC_SETTINGS` in `tests/test_installer_static.py`. `tests/conftest.py`'s `_isolate` blanks it like `HA_WEBHOOK_URL`.
- `HA_PLAY_WEBHOOK_URL` is a secret: never logged, never returned by a route, never in a payload. A failure logs the host and the kind of failure only (`ha._host`, as `ha._post` does).
- No live network in tests. The Home Assistant call has a miss test (no answer) and an HTTP-error test.
- Phone-first: no horizontal scroll at 412 px and 360 px, tap targets at least 44 px, contrast at least 4.5:1. A new text colour goes in `TOKENS` in `tests/test_theme_ui.py`; reuse existing tokens (`--ok-text`, `--ink-2`) and add none. Every UI change gets a Playwright check, exercised on the view's second visit too. Wire a view's listeners once (`wireX()`), never inside `showX()`.
- Public repo: placeholder names only outside `docs/superpowers/` (`media_player.family_room_tv`, `ha.example.com`, `192.168.1.100`); `tests/test_hygiene.py`.
- Exact wording from the spec: "Opening Disney+ on the Family Room TV…", "Disney+ is open on the Family Room TV.", "The TV is ready. {shelf}: go get it!", "The TV didn't answer. Try the remote.", "Sent to the TV.", "Couldn't reach the TV. {title} is on for tonight; use the remote.", "Our digital copy · Fandango at Home", "Play on the Family Room TV", "Start the disc", "Stream it", "Stream it on {name}".
- Conventional Commits, author `SDNick484 <SDNick484@users.noreply.github.com>`, one PR per task, `sh scripts/gate.sh` green before each PR. OpenRC and `vim` in docs. Tasks 4 and 5 are **(M)**: their PR descriptions end with a "Try it" note.

## Review Focus

1. **Home Assistant not answering.** Down, over 5 s, or HTTP 500: the play route is a 502 with the spec's sentence, the movie is still on for tonight, the webhook URL is nowhere in the log or the answer. Tests in Task 3.
2. **Play choosing something we'd pay for.** A movie `flatrate` only on a Considering or Ignore service, on an unknown provider, or rent-only has no stream option and `mode: "stream"` is a 409; a digital copy opens Fandango at Home even when that service is set to Ignore. Tests in Task 3.
3. **A stale confirmation.** The TV was on Netflix all evening and Play asks for Disney+: the old event never confirms; the TV already on Disney+ confirms at once and opens the night's session. Tests in Tasks 3 and 4.
4. **A database from before the upgrade.** A v1 row with only a summary gives the same disc and digital answers before and after its next ownership check; `migrate()` twice changes nothing. Tests in Task 1.
5. **Stray and double taps.** The ▶ on a Surprise card doesn't open the movie's page, a second tap while the first is pending sends nothing, and both still hold on the second visit to the main page. Tests in Task 5.
